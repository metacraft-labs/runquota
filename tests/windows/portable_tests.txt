# Test files the `windows-compile-gate` CI job COMPILES AND RUNS natively on
# Windows.
#
# runquota's suite is POSIX-only by construction: of the files
# `scripts/run_tests.sh` discovers, roughly a third import `std/posix`
# directly and rather more than that drive a unix socket or a real
# `runquotad`. A Windows job that claimed to "run the suite" would either be
# a lie or a pile of skips, and a job full of skips passes by doing nothing --
# which is the failure this whole gate exists to prevent.
#
# So this file is the honest subset: the test files that are about behaviour
# that is NOT platform-specific, and that therefore have something to say on
# Windows. Each one was verified to compile and pass on a native Windows
# checkout with no sibling repositories and no Nix.
#
# Excluded on purpose, and worth knowing why:
#   * everything touching `std/posix`, a unix socket, or a live daemon -- the
#     platform-specific half, covered on the Linux/macOS legs;
#   * the `t_observation_store_*` files -- they are platform-neutral in
#     principle but need an `sqlite3` on PATH, which the Windows runner does
#     not provide. The Nix dev shell DOES provide it (`pkgs.sqlite` in
#     `devShells.default`); it did not when this file was written, and that
#     sentence read as though the tool were missing everywhere. It is
#     missing on this job only, so the Linux and macOS legs are where these
#     files are actually exercised;
#   * `tests/unit/t_windows_compile_gate.nim` -- it cross-checks
#     `--os:windows` FROM a POSIX host, so running it on Windows would be a
#     native check pretending to be a cross one.
#
# Adding a row means asserting the file passes on Windows. The job's floor
# check refuses to run a shorter list than this one without the workflow
# being edited too, so shrinking it is a deliberate act rather than a
# silent one.

tests/compatibility/t_c_abi_layout.nim
tests/compatibility/t_protocol_codec.nim
# The build-wait pressure wire form: the finish's expected-duration ack, the
# `PressureReport` round-trip, the bound on a report's waits, and the pressure
# message kinds. Pure byte-string codec, no `when defined` guards, no daemon
# and no sqlite3 -- the sibling of `t_protocol_codec` for this feature.
tests/compatibility/t_pressure_codec.nim
tests/unit/t_version.nim
tests/unit/t_standalone_capture_rules.nim
tests/unit/t_packaging_contract.nim
# The daemon's build-wait pressure aggregation as pure functions of the reports
# and an injected clock: clamping, the decaying averages, and how waits are
# binned and counted as long. No `when defined` guards, no live daemon and no
# sqlite3; the real daemon, real sockets and a real queued `runquota run` are
# exercised on the platform-specific legs (Linux `t_build_wait_pressure`,
# Windows `t_build_wait_pressure_windows`).
libs/runquota_daemon/tests/t_pressure_metrics.nim
# Windows-SPECIFIC rather than platform-neutral, and here because it needs
# neither a daemon nor sqlite3: the host-state-directory DACL rule, row by
# row, against real directories whose ACLs `icacls` writes. Nothing else on
# this job exercises the Windows half of that trust check.
tests/unit/t_host_state_directory_rules.nim
# The owner id: pinned SID-hash vectors plus THIS process's id checked
# against the SID `whoami /user` reports. Needs neither a daemon nor
# sqlite3, and its Windows arm is the only place the named-pipe owner rule
# is exercised on this job.
tests/unit/t_owner_identity.nim
# The deadlock-test watchdog (`tests/support/child_watchdog`): a real wedged
# child and grandchild, the grandchild's pid checked against the kernel's own
# liveness answer. Needs neither a daemon nor sqlite3, and the Windows arm of
# that helper -- Job Object, parent-pid walk, native command-line inventory --
# is exercised nowhere else on this job.
tests/unit/t_child_watchdog.nim
# `runCapturedProcess`'s Windows arm: one drain thread per output stream, which
# must never allocate from the Nim heap, because Nim 2.2 under ORC never gives
# a finished thread's allocator pages back. The POSIX arm is a `poll` loop and
# has no threads, so this job is the only place the drains run at all.
# `t_child_process_partial_reads` pins that a pipe read in separate pieces is
# captured whole; `t_child_process_capture_memory` bounds resident growth over
# 2,000 captures and echoes 4 MiB without a deadlock. Both re-execute their
# own binary as the child, so they need no shell, no daemon and no sqlite3.
# Before they were added here, both were cross-compiled with mingw-w64 and run
# under Wine 11.0 on Linux at runquota e7f7246: they pass, with growth 522 B
# per call. The pre-fix drain (4bf105c) grew 164,528 B per call and failed.
libs/runquota_core/tests/t_child_process_partial_reads.nim
libs/runquota_core/tests/t_child_process_capture_memory.nim
# The pure parts and the named-semaphore token bookkeeping of the Windows
# `runquota jobserver` bridge: `MAKEFLAGS` composition, joining an inherited
# bridge, and widening/narrowing a real semaphore. Needs neither a daemon nor
# sqlite3; the POSIX sibling (`t_jobserver_bridge.nim`) drives the FIFO instead
# and is excluded here.
tests/unit/t_jobserver_bridge_windows.nim
# Windows Job Object CPU accounting and the `--cap` CPU-rate ceiling at the
# `runquota_process` launcher level: a grandchild's CPU counted against the
# tree, and a one-core cap holding a multi-burner tree near one core. Launches
# ITS OWN binary as the worker, so no shell, no daemon and no sqlite3; the cap
# case skips on a host with fewer than three cores.
tests/integration/t_windows_job_object_cpu.nim
# The admission order as pure functions of a simulated clock: the priority,
# cache-deadline, starvation and arrival keys, fair-share with a decaying
# per-group CPU figure, and DRF (and `share-between-users = none`) across
# owners. No `when defined` guards, no live daemon and no sqlite3; the real
# daemon, real named pipe and a real queued admission are exercised on the
# Windows integration leg (`t_session_group_admission` Windows arm).
libs/runquota_admission/tests/t_admission_order.nim
# The daemon's owner decision for `UpdateSessionGroup`: a group's attributes
# change only for the owner the daemon read from the connection, two owners may
# hold the same group name independently, and a connection with no credentials
# owns nothing. A real `RunQuotaDaemon` object with a hand-built `PeerIdentity`
# (the only stand-in -- a test process cannot connect as a second identity),
# no live daemon and no sqlite3. This is the whole of the owner-check coverage
# on Windows, where the integration case (`t_session_group_admission`'s
# `update_refused_for_other_uid`) is a capability record, not a real
# second-identity connection, for the same reason it is one on macOS.
libs/runquota_daemon/tests/t_update_session_group_owner.nim
# The host file's `[admission]` table as pure functions of `runquota_daemon`'s
# internals (`{.all.}`): the `order`, `max-wait` and `share-between-users` keys
# validated and put in force, the `--admission-max-wait-millis` flag winning
# over the file across reloads, a file that does not parse changing nothing,
# and `runquota config set` writing the three keys. No live daemon, no socket
# and no sqlite3.
libs/runquota_daemon/tests/t_host_config_admission.nim
# The host-config reload as pure functions of `runquota_daemon`'s internals
# (`{.all.}`): a reload promotes what now fits in the pass itself, a shrink
# never revokes a granted lease, a file that does not parse changes nothing,
# removing the file returns to the built-in defaults, and a flag still wins
# after a reload. No live daemon, no socket and no sqlite3.
libs/runquota_daemon/tests/t_host_config_reload.nim
